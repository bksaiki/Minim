# Bootstrap: start from the expanded prelude

Implementation plan.  The design is settled; what follows is the phase
breakdown, one phase per commit.

This is the first of two PRs.  It checks in the prelude already expanded into
core forms, a *boot file*, which startup evaluates instead of expanding the
prelude.  The expander's source doesn't change.  The second PR rewrites the
expander in normal Scheme, regenerating the boot file with itself, then
removes what only unexpanded code needed: internal `define` and
`define-values` in the evaluator.

## Working policy

- **Pause after each phase for review.** Do not begin the next phase until the
  current one has been looked at.
- **Do not commit.** The author of the change leaves the working tree dirty;
  commits are made by the repository owner.
- **Run only the tests relevant to the phase.** The full suite runs once, at
  the end, after the last phase.
- **Comments stay succinct**, and notes about *process* (what was tried, what
  a phase decided, why an ordering was chosen) belong in this document, not in
  source comments.
- **Design docs are synced after the last phase**, not during the phases, so
  they never describe an intermediate state.  Each phase records its decisions
  in this document instead.
- **Design docs stay succinct**: only the details a reader needs to understand
  the current implementation, said in as few words as possible.

## Context

`src/prelude.scm` is embedded as source (`cmake/embed.cmake`, the array
`minim_prelude_scm`), and `minim_prelude_init` (`src/prelude.c`) reads and
evaluates each form.  The expander comes first and runs unexpanded, so it is
written in core forms only; once `%expand` is defined, every later form is
expanded as it loads.  So every startup expands the derived forms and the list
library:

| Run | Startup |
|---|---|
| release, 20 runs | about 0.65 s, so about 33 ms each |
| ASan, stressed (`MINIM_GC_STARTUP=1`, 1-byte nursery) | 1.8 s |

Stressed startup is why `MINIM_GC_STARTUP` exists: the stress copies stress
only the program, and `startup_stress` stresses startup once (`testing.md`).

## Design

**The boot file**, `src/prelude.boot`, is checked in: the prelude's forms,
expanded, one top-level form per line.  It is embedded as the source is
today, and `minim_prelude_init` evaluates its forms *without* expanding them,
through a new internal entry point, `minim_eval_expanded`, that skips
`%expand`.

**Generating it.**  A driver, `tools/boot.c`, links `libminim` (so the running
expander is the one built from the current boot file), loads
`tools/boot.scm`, reads `src/prelude.scm` with `minim_read_file`, and writes
each form's expansion.  It expands without evaluating: the running system
already has every global and macro the prelude defines.  `%boot-form` in
`tools/boot.scm` does the per-form work:

- A top-level `begin` is spliced, as `%expand` does.
- A `define-syntax` is expanded (which registers the macro, so later forms
  see the new definition) and written as `(%define-macro! 'name 'spec)`,
  since a transformer is a closure and can't be written.  `%define-macro!`
  is factored out of `%expand-define-syntax` in the prelude, so loading the
  boot file rebuilds the macro.  The spec is plain data: the prelude's macros
  are written directly, not generated by other macros.
- Anything else is `(%expand form)`.
- It fails if expansion added to `%top-renames`: a fresh global made by a
  macro has no name the boot file can refer to.

**Names.**  Expansion renames locals to uninterned symbols, which print as
their base names, so two `x`s would read back as one.  Before writing,
`%boot-form` replaces each uninterned symbol with an interned `x.N`, `N`
counting distinct symbols of each base name within the top-level form, so a
change to one form doesn't renumber the others.  A symbol is interned when
`(string->symbol (symbol->string s))` is itself.  `x.1` reads as a symbol.

**Up to date.**  A CMake target, `boot`, regenerates `src/prelude.boot` in the
source tree; a test, `boot`, generates it into the build tree and compares.
Since the built `minim` starts from the checked-in file, a passing test also
means the file reproduces itself.  An expander change takes two
regenerations: the first expands with the old expander, the second with the
new one.

## Phases

### Phase 1 - Writing expanded forms

- `src/prelude.scm`: `%define-macro!`, used by `%expand-define-syntax`.
- `tools/boot.scm`: `%boot-form` and the renaming.
- `tools/boot.c` and its CMake target `boot_gen` (not built by default):
  writes the boot file to a given path.

Separate because it builds and checks the writer before anything depends on
its output.

Tests:

- `tests/repl/boot.scm` (new), which loads `tools/boot.scm`: renaming (two
  distinct `x`s get `x.1` and `x.2`, the same symbol one name, interned
  symbols unchanged, numbering restarting per form), `begin` splicing,
  `define-syntax` written as `%define-macro!`, and a `%top-renames` failure.
- A first full generation, read back and evaluated in a fresh process
  without expansion, running a few library calls (by hand, recorded here).

```sh
cmake --build --preset dev && ctest --preset dev -R 'boot|expan'
```

### Phase 2 - Start from the boot file

- `src/prelude.boot`: the first generated file, checked in.
- `CMakeLists.txt`: embed `src/prelude.boot` instead of `src/prelude.scm`;
  the `boot` target and test.
- `src/prelude.c`, `src/eval.c`: `minim_eval_expanded`, declared in a new
  internal header.

Separate because it changes what every program starts from, and measuring
startup needs it alone.

Tests: the full suite, since everything now runs on the boot file; the
`boot` test.  Measure startup against `main`, run alternately: release, 20
runs; and ASan stressed (`MINIM_GC_STARTUP=1 MINIM_GC_NURSERY_BYTES=1`).

```sh
cmake --build --preset dev && ctest --preset dev && ctest --preset stress -j 8
```

### Phase 3 - MINIM_GC_STARTUP

Decide with Phase 2's measurement (see Open items).  If it goes: the
environment's settings apply from the start of `minim_init`;
`MINIM_GC_STARTUP`, `program_config`, and `minim_gc_finish_startup` are
removed; every stress copy stresses startup; `test_startup` and
`startup_stress` are removed or reduced to what remains; the
`gc-settings-bad-startup` script test goes.  If it stays, record why here.

Separate because it changes test coverage and an environment variable, not
how the prelude loads.

```sh
cmake --build --preset dev && ctest --preset dev && ctest --preset stress -j 8
```

Sync the docs: `prelude.md` (the boot file, how to regenerate it and when

## Open items

### When does MINIM_GC_STARTUP go?

Stressing startup in every stress copy is the simplest coverage, but costs a
stressed startup per test.  Without expansion it should be far below 1.8 s.

Provisionally remove it if, with startup stressed in every copy, `ctest
--preset stress -j 8` takes at most 25% longer.  Otherwise keep it, and
reconsider when the lexical-address pass speeds up evaluation.

### What format is the boot file?

One top-level form per line keeps the writer trivial and makes a diff name
the forms that changed, but those lines are long.  A pretty-printer makes
diffs within a form readable, at the cost of writing one.

Provisionally one form per line.  Reopen if reviewing boot diffs proves
painful in the second PR, which regenerates it most.
